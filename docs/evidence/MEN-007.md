# MEN-007 manual adapter evidence

## Outcome

The installed `menaxvi` CLI can validate an approved workflow, render a deterministic operator plan, and bind supplied results to that plan. The path uses only local JSON resources and Python standard-library code. It does not select or call a model, provider, network service, filesystem tool, or publishing runtime.

## Operator commands

```bash
menaxvi workflow validate \
  --root . \
  --workflow workflow.reviewed-campaign-message@1.0.0

menaxvi workflow plan \
  --root . \
  --workflow workflow.reviewed-campaign-message@1.0.0 \
  --execution-id exec-men-007 \
  --inputs inputs.json \
  --output plan.json

menaxvi workflow record \
  --plan plan.json \
  --results results.json \
  --output record.json
```

`workflow validate` checks the active workflow, task, role, skill, and approved provenance references. It also checks local task and workflow dependency graphs and workflow gate targets.

`workflow plan` rejects missing or unknown workflow inputs. It orders workflow nodes and task steps by their declared dependencies. The output contains the workflow purpose, operator instructions, gates, policies, failure policy, evidence policy, and a SHA-256 digest. The same validated inputs produce the same plan.

`workflow record` verifies the plan digest and execution ID. It requires one result for each planned node and gate. It checks dependency completion, gate decisions, required human evidence, and policy gate consistency. The output is bound to the plan and has its own SHA-256 digest.

## Automated evidence

```bash
python3 -m unittest tests.test_manual_workflow -v
```

The focused suite covers:

- approved catalog validation;
- deterministic plan rendering and dependency order;
- missing and unknown input rejection;
- completed execution recording;
- failed-node recording with a gate that did not run;
- tampered-plan and invalid-decision rejection;
- the public CLI path from validation through result recording.

## Review notes

The adapter is additive. It reuses the canonical catalog contracts but does not change them. Rollback removes `tooling/menaxvi/manual.py`, the `workflow` CLI branch, its tests, and this evidence note.

## Residual risks

- This adapter validates the contract subset required for manual operation. The canonical schema loader remains the authority for full JSON Schema validation.
- A human result states whether a gate passed or failed because the current Workflow schema does not identify which free-form decision option is successful.
- Plan and result files can contain customer inputs and outputs. Operators must store them according to the workflow evidence and retention policy.
- The adapter records results but does not append them to the separate hash-chained runtime evidence log. Integration with that boundary remains a later runtime concern.
